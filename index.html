04 / WHAT THE SOURCE DOES

Read the real workflow.

References identify the 345-line baseline behavior. Revised behavior is called out explicitly.

01

Root and terminal setup

The original self-relaunches with sudo -E, checks whiptail and creates logs. The revision requires explicit sudo, validates dependencies and terminal size, then creates private logs.

Original L14–35
Inspect help safely
bash disk-explorer.improved.sh --help

Expected: command-line options without root or TUI setup.

02

Rank files and directories

The original scans /, /usr or a custom du path. The revision can start at --root, preserves NUL-separated paths and reports partial scans with task exit 3.

Original L38–58, L137–148
Start analysis at a chosen path
sudo bash disk-explorer.improved.sh --root /var

The TUI opens on /var with maintenance locked. Files use apparent bytes; directories use allocated usage.

03

Inspect with read-only ncdu

The original opens a writable root browser. The revision disables deletion and the built-in shell with repeated -r. Installing ncdu, if needed, is gated separately.

Original L91–134
Equivalent read-only ncdu invocation
sudo ncdu -r -r -x /var

Requires installed ncdu. The revision also uses --ignore-config when advertised by the installed help.

04

Read the private result logs

The original offers a master log and delete-all. The revision uses a separate private directory, unique task names and actual exit codes; log deletion is not offered.

Original L62–87, L151–184
Inspect revised log metadata
sudo ls -ld /var/log/disk-explorer-improved
sudo ls -l /var/log/disk-explorer-improved

After successful setup: directory 0700, new log files 0600. Protect the filesystem metadata in these logs.

05

Keep maintenance explicit

The original offers broader deletion, truncation and purge. The revision unlocks only APT cache cleaning and archived-journal vacuum; both choices start OFF with a default-No prompt.

Original L203–214, L227–282
Explicitly enable maintenance
sudo bash disk-explorer.improved.sh --enable-maintenance

The flag unlocks entries; no cleanup runs at startup. Maintenance remains system-wide even with --root.

06

Preview package removal only

The original filters the simulation through grep and also offers automatic purge. The revision keeps complete simulation output and status; it never executes autoremove.

Original L209, L217–224, L241
Read-only APT simulation
sudo apt-get -s autoremove --purge

APT reports proposed actions or a real error. The future package set may change after this simulation.

07 / TROUBLESHOOTING AND LIMITS

Read the whole result.

These are diagnostic paths for possible failures, not observations from a production run.

Why do find, du and df disagree?
File ranking uses apparent bytes. Directory usage is allocated space with overlapping parent/child totals. Filesystem accounting, hard links, deleted-but-open files and mounts can differ. A large path is not automatically safely reclaimable. The original offers both views at L38–58; the revision labels the metrics.
Why is a mounted data disk missing from the root scan?
The original uses -xdev/-x at L39–57 to restrict traversal by device/filesystem. Choose the mount as the revised analysis root. A report of / is not every filesystem.
Analyze a separate mount
sudo bash disk-explorer.improved.sh --root /mnt/data

Use an existing mount on your host; /mnt/data is illustrative.

Why does a revised task return exit 3?
find or du could not read every entry, so the result is partial. Inspect the escaped errors. Files may disappear, permissions can deny access and storage can fail. Other nonzero task codes also require log inspection.
Why is journal usage still above 100M?
Vacuum removes archived journals while disk-usage also includes active files. The revision does not force rotation or promise a 100M total. Review retention before enabling it. Official journal reference.
What if whiptail is missing or the terminal is too small?
Use an interactive terminal at least 72 columns × 20 rows. Install the TUI through your normal package process. The revision fails before launching an oversized dialog and does not silently install prerequisites.
Optional prerequisite installation
sudo apt-get update
sudo apt-get install whiptail
Does analysis mode write anything?
Yes: private logs and temporary scan/sort records. Its analysis entries change no scanned data, and ncdu disables deletion and shell. Maintenance and package installation remain gated. The live filesystem can change independently.
Can failed cleanup be rolled back?
No. The revision records the failure and stops later actions. Earlier successful cleanup remains completed. Cancellation or SIGKILL cannot restore deleted data. Review retention and recovery requirements before enabling maintenance.
How do I publish this in another repository?
Copy GoLive's contents as the new static site root: index.html and both scripts. Keep them together for relative downloads. All assets are inline; no parent repository, account or CDN is required.
Verification scope: Bash syntax, ShellCheck and isolated fixture/mocked-command checks cover the revision. Actual whiptail/ncdu behavior and Debian/Ubuntu maintenance still need controlled acceptance testing.
